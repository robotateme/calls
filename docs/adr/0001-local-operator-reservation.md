# ADR-0001: Calls держит только локальную бронь оператора

Status: Accepted

## Проблема

Несколько workers могут одновременно искать оператора. Без защиты один оператор
может попасть в два звонка.

При этом Calls не владеет настоящей доступностью оператора. `available` и `afk`
приходят извне.

## Решение

Calls хранит только короткую бронь:

- `operators.reserved_call_id`;
- `operators.reserved_at`.

`available` и `afk` остаются внешними данными.

После `connected` Calls снимает бронь, но не ставит `available=true`.

## Выбор оператора

Оператор подходит, если:

- `available=true`;
- `afk=false`;
- `reserved_call_id is null`.

Выбор оператора и запись брони идут в одной транзакции БД.

## Снятие брони

Можно снять бронь только у оператора, где `reserved_call_id` равен текущему
`call_id`.

Нельзя очищать чужую бронь.

## Старые брони

Если worker умер, бронь может зависнуть. Её чистит команда:

```bash
php artisan calls:operator-reservations:release-expired
```

## Нельзя

- Использовать `available=false` как бронь Calls.
- Ставить `available=true` после `connected`.
- Считать, что Calls управляет разговором после соединения.
- Снимать бронь без проверки `reserved_call_id`.

## Минусы

- Нужна cleanup-команда для старых броней.
- Нужны тесты от гонок между workers.
- Если появится отдельный operator-service, нужен отдельный договор
  reserve/release.

## Отклонили

- Менять `operators.available` внутри Calls.
- Не хранить бронь вообще.
- Выносить выбор оператора в отдельный сервис сейчас.
